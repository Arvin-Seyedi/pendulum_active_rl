## 5. Offline RL direction

Advisor preference:
- learn from logged data generated by the physical/existing controller
- do not rely only on simulation
- do not merely mimic the controller
- aim to improve performance/safety

Behavior cloning asks:
> What action did the LPV controller take?

Offline RL asks:
> Among supported state-action trajectories in the dataset, which actions lead to better long-term outcomes?

Historical literature direction was IQL first, followed by CQL / TD3+BC / offline
constrained RL as relevant. Experiment 06 subsequently tested IQL only in a
technical pilot and diagnostics; it remains unfinished. No successor algorithm
or full study is authorized by this context document.

Important limitation:
- if the expert dataset is nearly deterministic and concentrated around nominal operation, the learner may have insufficient action diversity/support to improve beyond the expert
- richer data should include different initial conditions, operating points, uncertainties, disturbances, and near-boundary states

Typical offline transition:
`(s_t, a_t, r_t, s_{t+1})`
plus safety margin/cost, reference, operating condition, and other relevant context.

## 6. Literature already reviewed

### Residual Reinforcement Learning for Robot Control — Johannink et al.
Core idea:
`u = pi_H(s) + pi_theta(s)`

A conventional controller handles known behavior; RL learns an additive correction for hard/unmodeled effects.

Important:
- still interacts online with the environment
- not fixed-dataset offline RL
- learned residual does not automatically inherit formal safety guarantees

### Residual Reinforcement Learning from Demonstrations — Alakuijala et al.
Core idea:
1. behavior cloning from demonstrations produces a base policy
2. freeze the base
3. learn an additive residual policy

`u_final = pi_b(s) + pi_r(s,u)`

Important:
- residual stage still uses environment interaction
- therefore not the same as the advisor's offline-only direction

IQL was subsequently studied in Experiment 06; see the current evidence below.
The literature notes above remain background, not an approved implementation plan.

## 7. Active expert-query idea

Conceptual loop:

`initial offline dataset`
`-> learner identifies uncertain/risky region`
`-> learner requests expert/controller rollout there`
`-> add data`
`-> retrain`
`-> repeat`

Uncertainty and risk are separate.

Proposed uncertainty measure:
- train an ensemble of learned policies on bootstrap samples of the initial dataset
- evaluate all policies at a candidate state
- use policy disagreement as epistemic uncertainty

For policies `pi_1, ..., pi_N`:

`U(s) = Std[pi_1(s), ..., pi_N(s)]`

Safety criticality is determined separately from the safety margin.

Possible query principle:
- high uncertainty
- small positive safety margin
- optionally large distance from existing dataset

Important caveat:
- the expert/controller itself may fail in some regions
- therefore expert exploration cannot assume the teacher is universally safe

## 14. Scientific standards

Always:
- distinguish empirical evidence from guarantee
- do not claim learned-policy safety is guaranteed unless proven
- do not assume action clipping implies state safety
- do not claim novelty without literature review
- use fair baselines and equal data budgets for targeted-vs-random comparisons
- report average and worst-case behavior
- preserve raw safety-state values before plotting/clipping transformations
