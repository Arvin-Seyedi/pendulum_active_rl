## 1. Main research direction

The broader area is safe reinforcement learning for nonlinear control.

A major prior direction is safe RL via diffeomorphic/state-barrier transformations. The user's earlier work includes safe RL for power-electronics control and later extension toward drilling control.

The current drilling research question has evolved toward:

> Can a learned controller improve upon an existing barrier-LPV drilling controller using data generated by that controller, while preserving or improving safety?

The advisor prefers a direction centered on offline RL from data collected using the physical/existing controller, not merely imitation.

A newer advisor idea is:

> During learning, can the learner identify risky, uncertain, or poorly covered operating regions and ask the existing controller to collect additional data specifically in those regions?

Once new data are requested, this is no longer strictly fixed-dataset offline RL. It is closer to active data collection / iterative batch RL / active expert querying around an offline-RL core.

## 3. Drilling safety constraints

Desired bit velocities:
- axial velocity: `v_d = 0.001 m/s`
- rotational speed: `w_d = 10 rad/s`

Rotational error:
`e_w = w_b - w_d`

Bounds:
- `k_wl = -4.77`
- `k_wu = 5.7`

Therefore absolute bit rotational speed must remain:

`5.23 < w_b < 15.7 rad/s`

Axial error:
`e_v = v_b - v_d`

Axial bounds are state-dependent:

`K_vl(e_w) < e_v < K_vu(e_w)`

The transformed axial and rotational errors are used by the LPV controller as scheduling variables.

## 5. Offline RL direction

Advisor preference:
- learn from logged data generated by the physical/existing controller
- do not rely only on simulation
- do not merely mimic the controller
- aim to improve performance/safety

Behavior cloning asks:
> What action did the LPV controller take?

Offline RL asks:
> Among supported state-action trajectories in the dataset, which actions lead to better long-term outcomes?

Historical literature direction was IQL first, followed by CQL / TD3+BC / offline
constrained RL as relevant. Experiment 06 subsequently tested IQL only in a
technical pilot and diagnostics; it remains unfinished. No successor algorithm
or full study is authorized by this context document.

Important limitation:
- if the expert dataset is nearly deterministic and concentrated around nominal operation, the learner may have insufficient action diversity/support to improve beyond the expert
- richer data should include different initial conditions, operating points, uncertainties, disturbances, and near-boundary states

Typical offline transition:
`(s_t, a_t, r_t, s_{t+1})`
plus safety margin/cost, reference, operating condition, and other relevant context.

## 6. Literature already reviewed

### Residual Reinforcement Learning for Robot Control — Johannink et al.
Core idea:
`u = pi_H(s) + pi_theta(s)`

A conventional controller handles known behavior; RL learns an additive correction for hard/unmodeled effects.

Important:
- still interacts online with the environment
- not fixed-dataset offline RL
- learned residual does not automatically inherit formal safety guarantees

### Residual Reinforcement Learning from Demonstrations — Alakuijala et al.
Core idea:
1. behavior cloning from demonstrations produces a base policy
2. freeze the base
3. learn an additive residual policy

`u_final = pi_b(s) + pi_r(s,u)`

Important:
- residual stage still uses environment interaction
- therefore not the same as the advisor's offline-only direction

IQL was subsequently studied in Experiment 06; see the current evidence below.
The literature notes above remain background, not an approved implementation plan.

## 7. Active expert-query idea

Conceptual loop:

`initial offline dataset`
`-> learner identifies uncertain/risky region`
`-> learner requests expert/controller rollout there`
`-> add data`
`-> retrain`
`-> repeat`

Uncertainty and risk are separate.

Proposed uncertainty measure:
- train an ensemble of learned policies on bootstrap samples of the initial dataset
- evaluate all policies at a candidate state
- use policy disagreement as epistemic uncertainty

For policies `pi_1, ..., pi_N`:

`U(s) = Std[pi_1(s), ..., pi_N(s)]`

Safety criticality is determined separately from the safety margin.

Possible query principle:
- high uncertainty
- small positive safety margin
- optionally large distance from existing dataset

Important caveat:
- the expert/controller itself may fail in some regions
- therefore expert exploration cannot assume the teacher is universally safe

## 8. Pendulum-v1 proof-of-concept

Purpose:
Test active expert-query logic in a simple continuous-control environment before returning to drilling.

Environment:
`Pendulum-v1`

Internal state:
`x = [theta, omega]`

Gym observation:
`[cos(theta), sin(theta), omega]`

Action:
continuous torque clipped to:
`u in [-2, 2] N*m`

Target:
- `theta_d = 0`
- `omega_d = 0`

### PD expert

Controller:
`u = -Kp*theta - Kd*omega`

Parameters:
- `Kp = 8`
- `Kd = 2`
- max torque = `2 N*m`

The PD controller plays the role of the existing drilling LPV controller.

### Safety constraints

- `|theta| <= 1 rad`
- `|omega| <= 3 rad/s`

Normalized safety margin:

`m(s) = min(1 - |theta|/1, 1 - |omega|/3)`

Interpretation:
- `m > 0`: safe
- `m = 0`: boundary
- `m < 0`: violation

## 11. Evidence through Experiment 10

Experiments 01–05, 06A, and 07–10 are complete and scientifically reviewed.
Experiment 06/IQL is unfinished. The chronological questions, evidence, decisions,
and commit/report references are in [docs/RESEARCH_DECISION_LOG.md](docs/RESEARCH_DECISION_LOG.md).
[CURRENT_STATUS.md](CURRENT_STATUS.md) is the immediate handoff; this section
replaces the former plan to implement D0 and ensemble uncertainty.

- Experiment 03 validated disagreement as an imitation-error diagnostic, with
  zero-tie, saturation and seed analyses. Error detection did not demonstrate
  better data acquisition or controller improvement.
- Experiment 04 found no reliable uncertainty-versus-random primary benefit at
  5,000 transitions: mean-return difference +15.644, 95% CI [−42.176, 59.125];
  violation-rate difference −0.200 percentage points [−0.550, 0.000]. Distance
  acquisition improved returns with safety tradeoffs. Uncertainty collection
  produced 90.77% near-equilibrium transitions.
- Experiment 05 reduced uncertainty collection redundancy from 89.56% at H200
  to 14.33% at H20, at approximately ten times the reset cost. Primary return
  difference +8.164 [−39.914, 52.714] and violation-rate difference −0.010 points
  [−0.090, 0.060] did not establish improvement. Neither redundancy reduction nor
  lower imitation error alone establishes better control.
- Experiment 06's expanded-data IQL critic was unstable. Freezing 138 safety-stop
  successor values prevented catastrophic divergence in a seed-41 diagnostic;
  a separate bounded readout prevented unbounded outputs but caused extensive
  saturation. Neither established accurate values or safe controller improvement.
  Both remain diagnostic-only. The deterministic PD data provide state coverage
  but no direct action alternatives at identical states; beyond-expert learning
  requires additional evidence or assumptions. The full IQL study was not launched.
- Experiment 06A found empirically safe one-action alternatives improving both
  200-step return metrics at 38/96 states above 1e−6 and 21/96 above 0.01; none
  exceeded 0.1. No alternative rescued any of 40 PD-unsafe states, and two
  introduced violations. These are oracle menu comparisons under PD continuation,
  not a deployable policy or formal safety guarantee.
- Experiment 07 used three fixed direct-multiple-shooting starts per state and
  independent Gymnasium replay. It found **0/40 safe witnesses** for the PD-unsafe
  sample, in either open-loop or feedback-tracking execution. All 48 converged
  non-equilibrium reference candidates failed open-loop safety; feedback tracking
  retained safety on all 16 references. Local solver failure and execution
  sensitivity did not establish physical unrecoverability.
- Experiment 08 independently certified **40/40 of those exact PD-unsafe states
  nonviable for the declared real-valued discrete model**, with zero unresolved
  PD-unsafe cases. All crossed an angle boundary by steps 2–23, using 128-bit
  directed-rounding intervals. There were no false nonviability certificates on
  the 16 reference controls; equilibrium has an exact zero-torque witness.
- Experiment 09 extended certification to **all 3,230 PD-unsafe points of the
  exact original Experiment 01 grid**, with zero unresolved primary model cases.
  A complete 6,561-state PD audit preserved the original observation/action dtypes
  while checking all 201 raw states. Archived labels, crossing times and legacy
  minimum margins reproduced exactly. There were 1,615 upper and 1,615 lower
  angle certificates, at steps 2–42, all at 128 bits. The smallest certified
  separation was 2.21447048634e−5 rad. The predefined gate skipped all eight
  alternative-controller searches and all optimization fallback solves in the
  full study; zero alternatives found is not an empirical search failure.
- Experiment 10 compared ten frozen controllers on all 3,331 empirically PD-safe
  points. LQR improved mean return by **+0.056165740 (4.10% mean-cost reduction)**,
  with **0/3,331 violations**, minimum raw margin 0.2, no observed per-state margin
  loss and minimum paired return difference 0. Its squared-torque effort increased
  **6.43%**, and its reward gain failed the frozen **+0.136939167** threshold.
  No tested controller passed the practical reward, effort or margin criteria.
  All **192 original optimization solves succeeded**, but **0/192 open-loop
  executions were safe** versus **192/192 feedback-tracking executions**.
  On the prespecified 64-state sample, the best-safe tracking oracle gained only
  **+0.000007367 mean return over matched LQR**, with no gains above 0.01.
  Tracking choices genuinely improved PD at all 64 states; open-loop oracles
  used PD fallback at all 64, which is not optimized success. Solver feasibility,
  outcome-selected oracle performance and empirical execution safety are separate.

Experiment 08 uses exact rational parameters and exact archived binary initial
states: `omega_next = omega + (15*sin(theta)+3*u)/20`,
`theta_next = theta + omega_next/20`, with `|u|<=2`, `|theta|<=1`, `|omega|<=3`,
and safety at all 201 samples of a 200-step horizon. The map is monotone on the
safe strip, and speed clipping is inactive on any step beginning in the safe set.
An extremal safe prefix followed by a strict crossing in the certifying direction
rules out all safe admissible sequences. An independent rational/Taylor checker
verifies every enclosure and the crossing; no solver-failure inference or global
viability-grid approximation is used.

These are model certificates, separate from Gymnasium observations. No global
implementation-rounding bound, continuous-time, uncertain-state, model-error,
or infinite-horizon guarantee is established. The references' empirical PD
witnesses do not become mathematical viability proofs. Experiment 08's selected
40-state sample could not characterize all PD failures;
Experiment 09 subsequently resolved every original grid failure under the same
real model. Neither study characterizes the complete continuous viable region.
The 3,331 PD-safe grid points remain empirical finite-horizon simulator evidence,
not a certified region for arbitrary states or modified policies.

For the original certified PD-unsafe points, rescue is impossible under the
specified model, torque bounds and safety constraints; further rescue searches
there would not test an achievable controller-improvement objective. This does
not establish PD reward optimality. Experiment 10 subsequently found limited
demonstrated performance headroom under its tested methods: a strong classical
LQR baseline accounts for almost all of the selected optimization oracle's gain.
This is not a proof of global optimality or absence of improvement under every
controller. The 64 optimization points are a frozen stratified diagnostic sample,
and deterministic repeats are verification, not independent statistical samples.
No mathematical safety guarantee for LQR or tracking was established.

Together, Experiments 09–10 motivate preserving Pendulum as a methodological
benchmark while evaluating control tasks/objectives with meaningful, safely
achievable learning headroom. Any future task must justify its objective, strong
classical baselines, counterfactual action support, and independent safety
evaluation before training. Do not alter objectives to manufacture favorable
results. Task selection requires a separate scientific design review; no new
experiment, safety filter, data collection, RL training, or IQL resumption is
authorized by this context update.

## 14. Scientific standards

Always:
- distinguish empirical evidence from guarantee
- do not claim learned-policy safety is guaranteed unless proven
- do not assume action clipping implies state safety
- do not claim novelty without literature review
- use fair baselines and equal data budgets for targeted-vs-random comparisons
- report average and worst-case behavior
- preserve raw safety-state values before plotting/clipping transformations

Current main research question:

> Can a learner use uncertainty and safety information to request targeted data from an existing controller in poorly covered, safety-critical regions, and can that targeted data improve a subsequent offline policy more effectively than the same amount of randomly collected expert data?
